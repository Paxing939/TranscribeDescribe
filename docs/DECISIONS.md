# Решения по реализации

Отступления от ТЗ и выбор там, где ТЗ оставляло вариант (§0).

## D-001. Сборка через MSYS2 UCRT64 (MinGW), а не MSVC — 15.10.2026

ТЗ (§11, п. 8; §12) требует таргет `x86_64-pc-windows-msvc`. На машине нет Visual Studio Build Tools, а их установка требует прав администратора (UAC); подтвердить её было некому. Поэтому сборка идёт тулчейном MSYS2 UCRT64: Rust 1.99 (`x86_64-pc-windows-gnu`), gcc 16, clang 23 (libclang для bindgen), Vulkan headers/loader, shaderc (`glslc`). Окружение — `scripts/env.ps1`.

Следствия:

- `whisper-rs-sys` рассчитан на MSVC: подставляет флаг `/utf-8` и ждёт имена библиотек `ggml.lib`. Локальная копия с двумя правками лежит в `third_party/whisper-rs-sys` и подключена через `[patch.crates-io]`:
  - флаг `/utf-8` — только для MSVC;
  - для GNU копируются `ggml*.a` → `libggml*.a`.
- whisper.cpp в MinGW-сборке открывает модель через narrow-путь (§11, п. 30). Модели лежат в `%LOCALAPPDATA%\CallScribe\models` — путь ASCII для этого пользователя. Для путей с кириллицей нужна MSVC-сборка или загрузка модели из буфера.
- Exe зависят от DLL рантайма UCRT64 (`libstdc++-6.dll`, `libgcc_s_seh-1.dll`, `libwinpthread-1.dll`). Они кладутся рядом с exe (скрипт `scripts/bundle.ps1`), в установщике — тоже.

Чтобы вернуться к MSVC: поставить VS Build Tools (C++), LLVM и Vulkan SDK, затем `rustup` с MSVC-тулчейном. Патч `whisper-rs-sys` для MSVC ничего не меняет.

## D-002. Внешние файлы при `callscribe process` переносятся в папку звонка — 15.10.2026

ТЗ: «раскладывает файлы по папкам», MKV после ремукса удаляется (F-52). Файл переносится (или ремуксится и удаляется) в `<calls_dir>/<звонок>/`. Флаг `--keep-source` копирует и оставляет оригинал.

## D-003. Две дорожки вместо трёх — 15.10.2026

ТЗ описывает 3 дорожки (микс, микрофон, звук системы) и 1 дорожку (микс). Для файла с двумя дорожками первая считается «Я», вторая — «Собеседник»; в саммари и транскрипт пишется предупреждение.

## D-004. Порог «нет речи» whisper.cpp отключён — 15.10.2026

`no_speech_thold` выставлен в 1.01, чтобы whisper.cpp не выбрасывал куски молча. Фильтр F-55 применяется в `PostProcessor` с порогами Whisper по умолчанию: `no_speech_prob > 0.6` и средний `logprob < -1.0`. Выброшенное остаётся в `transcript.json` с `dropped`.

## D-005. Пауза очереди на время записи — через heartbeat — 15.10.2026

Вместо флага «идёт запись» (§4.1) трей раз в ~30 с продлевает в SQLite отметку `recording_until` на 90 с. Если трей упал посреди записи, отметка истекает сама, и очередь не зависает навсегда.

## D-007. Границы сегментов — по энергии сигнала; сегменты на тишине отбрасываются — 15.10.2026

Whisper ставит начало сегмента в конец предыдущего окна, вместе с тишиной: реплика на 5-й секунде начиналась с 0:00. Поэтому:

- включены пословные таймкоды токенов;
- после распознавания границы сегмента подрезаются по RMS-энергии дорожки: кадры 20 мс, порог — пик дорожки минус 35 дБ, запас 100 мс;
- сегмент, в котором вообще нет звука выше порога, — галлюцинация на тишине («Thank you.», «Продолжение следует…») и помечается `dropped: "silence"`.

Служебные метки Whisper (`[BLANK_AUDIO]`, `(музыка)`, `*шум*`) помечаются `dropped: "non_speech"`.

## D-008. Установщик ставит программу в `%LOCALAPPDATA%\CallScribe` — ту же папку, где данные — 15.10.2026

NSIS-установщик Tauri в режиме `currentUser` кладёт exe в `%LOCALAPPDATA%\<productName>`. Это совпадает с папкой данных из §7.1 (`data.db`, `logs\`, `models\`). Конфликта нет: деинсталлятор удаляет только свои файлы, а галочка «удалить данные приложения» относится к `%LOCALAPPDATA%\com.callscribe.desktop`. Модели и история звонков при переустановке сохраняются.

## D-009. ffmpeg в установщике — сборка «full» — 15.10.2026

В установщик кладутся `ffmpeg.exe` и `ffprobe.exe` из PATH (winget, gyan.dev «full», GPL), по ~227 МБ. Поэтому установщик весит ~126 МБ. Для раздачи нужна LGPL-сборка «essentials» (§11, п. 31).

## D-010. Окно настроек правит только основные ключи — 15.10.2026

Форма (F-102) меняет основные параметры: общие, детект, OBS, модели, пресет LLM, хранение, оверлеи. Значения пишутся через `toml_edit`, комментарии сохраняются. Правила детекта, regex и blacklist по-прежнему правятся в `config.toml` (пункт меню «Открыть config.toml»). На первом запуске (конфига ещё нет) окно открывается само как мастер (F-103).

## D-006. sherpa-onnx: готовые shared-библиотеки k2-fsa, линковка под windows-gnu — 15.10.2026

F-60 (диаризация) и F-61 (GigaAM v3, Parakeet TDT v3) идут через официальный крейт `sherpa-onnx` 1.13.8 (крейт `callscribe-stt-sherpa`). Крейт по умолчанию скачивает статические MSVC-библиотеки (`static-MT`), и под GNU-линкер они не годятся.

Что сделано:

- Включена feature `shared`. Из релиза k2-fsa берётся `sherpa-onnx-v1.13.8-win-x64-shared-MT-Release-lib.tar.bz2` (C API, собран с `/MT`, без зависимости от MSVC CRT). Его `.lib` — импорт-библиотеки MSVC; GNU `ld` линкует их напрямую, а C API — чистый C, поэтому ABI между MSVC-DLL и MinGW-exe совместим. Ни `raw-dylib`, ни `libloading`, ни сборка из исходников не понадобились.
- Библиотеки лежат в `third_party/sherpa-onnx-lib` (скачивает `scripts/fetch-sherpa.ps1`; `prebuild.ps1` вызывает его сам). Путь передаётся через `SHERPA_ONNX_LIB_DIR` в `.cargo/config.toml` (`[env]`, относительный). `build.rs` крейта `sherpa-onnx-sys` сам кладёт DLL в `target/<profile>/`.
- Рантайм: `sherpa-onnx-c-api.dll`, `onnxruntime.dll`, `onnxruntime_providers_shared.dll` должны лежать рядом с exe. `prebuild.ps1` копирует их в `apps/tray/src-tauri/runtime/` (ресурсы `runtime/*.dll` попадают в папку exe). Рядом с exe они нужны ещё и потому, что в `System32` лежит свой, старый `onnxruntime.dll`.
- В CLI feature `sherpa` включена по умолчанию: на этой машине сборка и запуск проверены. Без неё (`--no-default-features --features vulkan`) движки `gigaam`/`parakeet` и `transcription.diarization` отвечают понятной ошибкой / предупреждением.

Выбор моделей:

- GigaAM v3 — RNNT с пунктуацией: `sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16` (170 МБ). CTC-вариант чуть меньше, но RNNT у GigaAM точнее.
- Parakeet — `sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8` (490 МБ). Язык определяет сама.
- Диаризация — `sherpa-onnx-pyannote-segmentation-3-0` + `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx` (рус/англ. речь, 28 МБ).
- Нарезка длинной записи — Silero VAD в ONNX (`silero_vad.onnx`, 0,6 МБ; формат GGML от whisper.cpp sherpa не читает), куски ≤ 20 с (GigaAM берёт до ~25 с).
- Архивы `.tar.bz2` скачиваются и распаковываются в `models_dir/<имя>/` (крейты `tar` + `bzip2`, без внешних утилит).

Ограничения: sherpa-onnx работает на CPU (GPU-сборка — своя, через `SHERPA_ONNX_LIB_DIR`); `no_speech_prob` и `avg_logprob` у этих движков нет (`None`, фильтр F-55 по ним не срабатывает); спикер диарики назначается реплике по наибольшему перекрытию, поэтому кусок VAD, в котором говорящие сменились без паузы, получает одного. Диаризуется дорожка «Собеседник» (и единственная дорожка записи); «Я» — всегда один человек. Номер говорящего хранится в `speaker_index` (с 1) у `Segment` и `Utterance`; `Speaker` и формат `transcript.json` остались прежними. При одном говорящем номера не пишутся.

## D-011. Whisper без переноса текста между окнами — 19.10.2026

На часовом созвоне вся дорожка собеседника превратилась в «Корректор А.Кулакова». В начале созвона было ожидание (тишина, музыка), там Whisper выдал титры из своих обучающих данных. Дальше каждое 30-секундное окно опиралось на предыдущий текст и повторяло их до конца записи. `no_context` очищает контекст только в начале `full()`, внутри одного прогона текст всё равно переносится.

Решение:

- `n_max_text_ctx = 0` — окна распознаются независимо, это аналог `condition_on_previous_text=False` в faster-whisper. На том же 20-минутном фрагменте «галлюцинаций» стало 4 из 141 сегмента, было 681 из 682.
- Глоссарий (`initial_prompt`) при этом влияет только на первое окно.
- Встроенный список типичных галлюцинаций («Корректор А.…», «DimaTorzok», «Продолжение следует…») применяется всегда, поверх `transcription.hallucination_blacklist`: в пользовательском `config.toml` хранится своя копия списка, и новые шаблоны туда сами не попадают.
